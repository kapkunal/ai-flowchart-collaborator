Three Architecture Approaches

How Claude reads and writes the Excalidraw canvas state

A

React + Vite Dev Server Recommended

React app with @excalidraw/excalidraw running via Vite. Exposes window.excalidrawAPI so Claude calls updateScene() and getSceneElements() via preview_eval. User draws in the browser; Claude reads state and responds in terminal.

Pros

  • Full Excalidraw feature set
  • Clean API — no hacks
  • Persistent scene state

Cons

  • npm install + build step to set up
B

File-Watched State Sync

Claude writes Excalidraw JSON to a scene.json file; the React app polls it every second and calls updateScene(). Good for async turn-taking where Claude generates a full scene offline before showing it.

Pros

  • Decoupled — Claude writes files, browser reads
  • Scene is always persisted on disk

Cons

  • Polling lag (1s delay)
  • Extra moving part (file watcher)
C

WebSocket Bridge

A lightweight Node.js server (ws) bridges Claude's tool calls to the browser canvas via WebSocket. Claude calls a tiny HTTP POST endpoint; server pushes to the browser instantly.

Pros

  • Real-time push, no polling
  • Two-way events (user draw → Claude notified)

Cons

  • Most complex — two servers to manage
  • Overkill for turn-by-turn interaction

Click an option to select it, then respond in the terminal. I recommend A — direct preview_eval is all we need for turn-by-turn; no extra infrastructure.
